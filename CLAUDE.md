# Дополнительно для Claude Code

- Задачу больше трёх файлов начинай в план-режиме; код пиши после согласования плана.
- Интерфейс проверяй во встроенном браузере на 360×800 и 1366×768 (`resize_window`: пресет `mobile` — 375 px, поэтому для
  360 задай ширину и высоту явно). В отчёте опиши, что именно видел; снимки не подписывай как «реальные», если их сделал не ты.
- Субагенты проекта лежат в `.claude/agents/`; у каждого одно направление и формат результата:
  - `security-auditor` — после изменений в `server/routes/`, `server/security/`, `server/domain/requests.js`, `server/domain/assistant.js` и перед публикацией; только читает и воспроизводит атаки на временной базе;
  - `ui-mobile-reviewer` — после изменений в `public/`; только измеряет и присылает таблицу находок;
  - `test-engineer` — регрессионный тест для каждой найденной ошибки; сначала красный, потом зелёный;
  - `content-writer` — демо-данные (`server/seed/`) и тексты интерфейса, только вымышленное;
  - `docs-chronicler` — `docs/` и журналы процесса, каждое утверждение с источником;
  - `release-engineer` — только по прямой команде человека.
- Команды: `/feature <ID из docs/ai/SPEC.md>`, `/bugfix <описание>`, `/verify`.
- Поручение субагенту пиши полностью: роль, файлы, которые можно менять, критерий готовности, формат отчёта.
  Текст поручения запиши в `docs/ai/PROMPTS_LOG.md` с пометкой «поручение агента».
- Начало сессии: прочитай `docs/ai/PROGRESS.md` и перескажи в пяти строках, где мы.
- Конец сессии: обнови `docs/ai/PROGRESS.md` и `docs/ai/PROMPTS_LOG.md`; ошибку запиши в `docs/ai/ERRORS.md`.
- `.env` и `data/` не читаешь, переменные окружения не выводишь. `git push`, `npm run seed`, `docker`, `ssh` — только после подтверждения человека (`.claude/settings.json`).
