# МГИМО Мания — концепт личного кабинета студента

> **Концепт для конкурса. Не является официальным сервисом МГИМО.** Все люди, оценки, номера зачёток,
> телефоны и адреса почты вымышлены. Знак «МГИМО Мании» — собственный, это не логотип вуза.

**Прототип: https://ai.neblanki.tech/** · [Маршрут для жюри](docs/JURY_GUIDE.md) ·
[Как создавался (PDF)](docs/PROCESS.pdf) · [Соответствие требованиям](docs/CONTEST_AUDIT.md) ·
[Видео с мобильного экрана, 2 мин](docs/video/demo-mobile.mp4)

**Версия 1.1.1 от 22 ноября 2026.** Номер виден на странице входа, в подвале кабинета и в ответе `/api/health`;
если на стенде его нет, стенд ещё не обновлён.

Кабинет помогает понять, куда идти на пару, что требует внимания в учёбе и что происходит
с заявкой. Студент подаёт справку, сотрудник своего факультета принимает решение,
а результат возвращается уведомлением и документом с кодом проверки подлинности.

По отзывам двух студентов, попробовавших кабинет, на главной появилась кнопка
«С чего начать» с тремя учебными действиями. Затем прошёл опрос 25 студентов: справка
нужна была 24 из них, 19 получают её лично и ждут дольше двух дней. Лёгкость заданий в кабинете
с телефона участники сами оценили в среднем на 4,4 из 5; 16 из 25 сочли все задания лёгкими, трудными
называли риск по дисциплине и перенос пары — по 3 голоса из 25. Причину риска мы вынесли на главную, и пятеро
из тех же 25 повторили задания на исправленной версии: их самооценка лёгкости — 4,4 против прежних 3,2.
[Ответы и расчёт](docs/evidence/survey-2026-11-22/) · [повторный замер](docs/evidence/survey-repeat-2026-11-22/).

**Проверено 22 ноября 2026, версия 1.1.1:** 115/115 автотестов и 604/604 браузерных проверок в 18 наборах
на ширинах 360 и 1366 px и на низких экранах телефонов, без ошибок JavaScript — в чистой копии репозитория
(`git clone`, `npm ci`), на временных базах и без внешнего ИИ: [сводка запуска](docs/evidence/release-1.1.1/run-summary.json).
Справка, форма и вход пройдены и в Safari на iPhone SE в симуляторе iOS — [снимки](docs/evidence/ios-simulator-2026-11-22/).
Как воспроизвести — ниже, в «Запуске».

**У каждого проверяющего свой демо-кабинет:** первый вход создаёт отдельную копию вымышленных данных,
и действия других посетителей её не меняют. Тот же кабинет во втором окне — по ссылке из «Ваш демо-кабинет».

Учёба, документы и связь с деканатом — в одном окне, с телефона и компьютера. Под кабинетом —
игровой слой из прототипа «Мании»: аватар и гардероб, питомец, виртуальный кампус вместо офиса
и пятиминутный перерыв-забег. Учебные действия доступны напрямую, независимо от игрового прогресса.

## Что внутри

**Обязательное ядро**

| Раздел | Что умеет |
|---|---|
| Вход и профиль | Логин и пароль, блокировка перебора, активные сеансы, смена пароля. Профиль: ФИО, факультет, направление, профиль, курс, группа, языки, куратор, контакты деканата |
| Расписание | Сегодня и неделя, аудитория с этажом и преподаватель. Отмены, переносы, новые аудитории, замены и доп. занятия подсвечены. Чётность недели, праздники, звонки, экспорт в календарь (.ics) |
| Успеваемость | 100-балльная шкала: баллы по контрольным точкам, прогноз и «сколько не хватает до „отлично“», зона риска, посещаемость, рейтинг в группе, стипендия. Сессия с консультациями и допуском. Электронная зачётка с графиком среднего балла и долгами |
| Заявки и справки | 10 видов справок и заявлений, автозаполнение из профиля, проверка полей, защита от дублей (повторная отправка открывает уже созданную заявку). Статус как у посылки с историей, срок в рабочих днях. Электронная справка — страница и PDF-файл с кодом проверки подлинности, бумажная — с местом выдачи |
| Уведомления | Новости деканата, изменения расписания со ссылкой на нужную пару, напоминания о дедлайнах за 3 дня и в день срока, статусы заявок, новые оценки. Фильтры, «прочитать все», живые всплывающие уведомления |

**Дополнительные возможности**

- **Кабинет деканата** (`dekanat.mo`): очередь заявок своего факультета с поиском по номеру и прямой ссылкой на заявку, решения с комментарием студенту, объявления факультету или группе, отмена пары и смена аудитории, журнал действий.
- **«Спросить деканат»** — помощник по данным самого студента. Поддерживает `OPENROUTER_API_KEY` и прямое подключение Anthropic (вызов только с сервера). Без ключа, при таймауте или ошибке провайдера отвечает по встроенным правилам; источник ответа указан в чате.
- **Кампус** — учебный корпус в разрезе: гардероб, деканат, аудитория, библиотека, студклубы и Лавка. Каждая зона ведёт в раздел кабинета, за прогулку — М-коины и вещи.
- **Аватар, гардероб и питомец** — питомец подсказывает про пару и дедлайн, растёт от фокус-сессий «Учимся вместе 25 минут».
- **Перерыв «Бегом на пару»** — оригинальный раннер по коридору корпуса: три дорожки, прыжок и подкат, кофе и зачётка-бонус. **5 минут в день**, лимит и счёт проверяет сервер.
- **Лавка МГИМО** — мерч за М-коины с цифровой копией для аватара; выдача оформляется заявкой.
- **Первые шаги** первокурсника, квиз, титулы, демо-тур для жюри.

## Запуск

Нужен Node.js 22.13 или новее (используется встроенный `node:sqlite`).

Репозиторий большой: в нём журналы и снимки всех прогонов проверок, PDF и ролик — около 180 МБ в последней
версии и около 300 МБ с историей. Для запуска и тестов хватит последней версии без истории:

```bash
git clone --depth 1 https://github.com/temurysega/vibe_code.git
cd vibe_code
npm install
npm start
```

Кабинет откроется на http://localhost:3000. Демо-данные создаются при первом запуске и строятся от
текущей даты по Москве: ближайшие переносы, дедлайн послезавтра, справка, которая скоро станет готова.

```bash
npm test
```

Автотесты проверяют изоляцию аккаунтов, безопасность, сохранение данных, основные сценарии и обработку ошибок ИИ. В Windows используйте `npm.cmd test`, если PowerShell запрещает запуск `npm.ps1`.

Проверка интерфейса в Chromium (не требует добавления зависимостей в приложение):

```bash
python -m pip install -r requirements-qa.txt
python -m playwright install chromium
python test/browser-smoke.py http://localhost:3000
python test/browser-flows.py http://localhost:3000
python test/browser-accessibility.py http://localhost:3000
```

Запускайте браузерные сценарии на отдельной тестовой базе: они создают заявки и обрабатывают их в деканате. Скриншоты и протоколы сохраняются в `docs/evidence/`.
Все 18 наборов разом, каждый на своей временной базе, — `python scripts/collect-evidence.py --output docs/evidence/<новая-папка>`:
наборы `browser-review-fixes` и `browser-review-1122` сборщик запускает с демо-кабинетами, как на стенде, и передаёт
второму папку кабинетов (`QA_SANDBOX_DIR`).

### Подключение OpenRouter

Скопируйте `.env.example` в `.env` и заполните **локально**, не публикуя ключ:

```dotenv
OPENROUTER_API_KEY=
OPENROUTER_MODEL=openrouter/free
AI_TIMEOUT_MS=15000
```

После изменения перезапустите сервер. `openrouter/free` — стартовый бесплатный маршрутизатор; можно указать выбранную модель из своего аккаунта. Доступность и лимиты зависят от провайдера. Если заданы оба ключа, приоритет у OpenRouter. Ключи не передаются браузеру, история беседы очищается при выходе. Сервер передаёт провайдеру вопрос и ограниченный снимок вымышленных данных вошедшего студента.

Интеграция использует [официальный Chat Completions API OpenRouter](https://openrouter.ai/docs/api/api-reference/chat/create-a-chat-completion). Без настоящего ключа тесты проверяют контракт через подмену API; успешность реального запроса нужно проверить отдельно.

### Публикация по ссылке

Для существующего VPS `ai.neblanki.tech`: [конфигурация и порядок обновления](docs/DEPLOYMENT.md).

- **Render**: New → Blueprint → этот репозиторий. `render.yaml` предусматривает **платный** сервис и постоянный диск для SQLite; секрет `OPENROUTER_API_KEY` задаётся в панели. Развёртывание не выполняется автоматически при скачивании проекта. Без постоянного диска Render теряет изменения файлов при перезапуске — [документация](https://render.com/docs/disks).
- **Docker локально**: `docker compose up --build -d`. Откройте http://localhost:3000. Именованный том сохраняет SQLite между перезапусками; `docker compose down` оставляет данные, опция `-v` удаляет их.
- **VPS**: Node.js 24, `npm ci --omit=dev`, постоянный `DB_FILE`, процесс под supervisor и HTTPS-прокси. Для публичного стенда установите `NODE_ENV=production`, `COOKIE_SECURE=1`, `TRUST_PROXY=1` только за доверенным прокси, а для отдельных демо-кабинетов — `DEMO_SANDBOXES=1` и `SANDBOX_DIR` на том же постоянном томе. Готовность — `GET /api/health`. В Compose порт привязан к localhost для подключения локального HTTPS-прокси.

Автоматический сброс базы по умолчанию отключён (`DEMO_RESEED_HOURS=0`). Команда `npm run seed` **удаляет текущие демо-данные** и создаёт их заново.

## Безопасность

- Студент определяется по сессии на сервере, а не по адресу: каждый запрос к заявке проверяет владельца, чужая отвечает 404. Деканат видит только свой факультет.
- Пароли — только хеш scrypt со случайной солью; после 5 ошибок вход блокируется на 15 минут.
- Сеанс — случайный ключ в cookie `HttpOnly; SameSite=Lax; Secure` (префикс `__Host-` в продакшене), в базе — SHA-256 от ключа. Сеансы видны и закрываются в профиле.
- CSRF-токен и проверка Origin для изменяющих запросов, экранирование вывода. CSP разрешает скрипты, стили и шрифты только со своего домена: шрифт Onest раздаётся локально.
- На стенде у каждого проверяющего свой демо-кабинет — отдельная SQLite; чужие заявки, объявления и сеансы не видны. Объявления и изменения расписания ограничены: 10 публикаций за 10 минут.
- Ключи сервисов — только в переменных окружения сервера (`.env` в `.gitignore`), в коде и браузере их нет.
- Минимум персональных данных: нет паспорта и СНИЛС, зачётка и телефон скрыты до нажатия, в браузере после выхода ничего не остаётся.

Подробности — в [docs/SECURITY.md](docs/SECURITY.md), устройство — в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Стек

Node.js без фреймворков (`node:http`, `node:sqlite`, `node:crypto`, `node:test`), фронтенд на
ES-модулях без сборки; PDF справки собирает `pdf-lib` ([ADR-013](docs/ai/DECISIONS.md)). Сейчас это один
сервер с файловой SQLite: локально он держит около 2 750 запросов в секунду без ошибок при 100 одновременных
пользователях без пауз ([замер](docs/evidence/load-2026-11-21/)). Для горизонтального масштабирования
потребуются адаптер PostgreSQL, миграции SQL и общие лимиты в Redis; одного изменения строки подключения недостаточно.
