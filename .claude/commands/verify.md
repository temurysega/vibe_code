Проверка текущего кода. Папка результата: `docs/evidence/$ARGUMENTS` (если пусто — придумай новое имя вида `verify-<дата>`;
существующие папки не перезаписывай).

1. `git status` и `git log -1 --format=%h` — запиши, какой код проверяется. Если есть чужие незакоммиченные правки — назови их в отчёте.
2. `npm test` с пустыми `OPENROUTER_API_KEY=` и `ANTHROPIC_API_KEY=`: число тестов и результат.
3. `python scripts/collect-evidence.py --output docs/evidence/<папка>`: каждый браузерный набор работает на своей временной базе,
   внешний ИИ отключён. Если упал — не повторяй молча: сохрани неуспешную папку, найди причину (код или тест, E-13), затем повтор в новой папке.
4. Отдельно, если менялись соответствующие файлы: `test/browser-migration.py` (не входит в сборщик).
5. Сравни `run-summary.json` с предыдущим (`docs/evidence/quality-fixes/run-summary.json`): число автотестов, число браузерных проверок,
   `browser_errors`, `tested_source_sha256`. Любое уменьшение числа проверок объясни.
6. Отчёт: команда → результат по каждому шагу; таблица «набор · пройдено/всего»; что не проверено
   (нагрузка, доступность из России, внешний ИИ, WCAG-аудит).
7. Обнови `docs/ai/PROGRESS.md`: «Последний зелёный прогон» со ссылкой на новую папку.
   Не делай `git commit`, `git push`, `npm run seed` без команды человека.
