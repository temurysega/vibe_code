# Архитектура

```
браузер (ES-модули, hash-роутер)
   │  JSON по HTTPS, cookie сессии + CSRF-токен
   ▼
server/app.js ── заголовки, CSRF, Origin, разбор JSON, маршруты, статика
   ├── routes/     auth · student · requests · play · dean · assistant
   ├── domain/     time · schedule · grades · requests · notifications · play · assistant
   ├── security/   password · session · auth · rateLimit · headers
   └── db.js ───── node:sqlite, файл на постоянном диске
```

## Сервер

- **Без серверного фреймворка**: HTTP, SQLite и криптография используют встроенные модули
  `node:http`, `node:sqlite`, `node:crypto`. SDK Anthropic и его транзитивные зависимости
  перечислены в `package-lock.json`; SDK нужен только для соответствующего провайдера ИИ.
- **Маршрутизатор** (`server/http/router.js`) — шаблоны вида `/api/requests/:id` и цепочки
  обработчиков: охранник (`requireStudent`, `requireDean`) → обработчик.
- **Время вуза** (`domain/time.js`) считается по Москве независимо от часового пояса сервера:
  чётность недели, праздники, семестры, звонки.
- **Расписание** (`domain/schedule.js`) = регулярные пары + журнал изменений (отмена, перенос,
  аудитория, замена, доп. занятие). Неделя собирается на лету, поэтому деканат меняет одну запись,
  а не перерисовывает расписание.
- **Успеваемость** (`domain/grades.js`): контрольные точки по 100-балльной шкале, прогноз по
  текущему темпу, пороги 60/75/90 и подсказка «сколько не хватает».
- **Заявки** (`domain/requests.js`): каталог видов с описанием полей → серверная проверка →
  статусы только вперёд → история и уведомление на каждом шаге. В демо заявка сама проходит
  шаги по плану, пока деканат не вмешается: электронная справка становится готовой примерно
  через 8 минут, чтобы жюри успело принять решение вручную (`DEMO_AUTOPILOT_SCALE`).
- **Уведомления**: адресат — вуз, факультет, группа или студент; напоминания о дедлайнах
  материализуются один раз по ключу.
- **Фоновые задачи**: шаги заявок раз в 5 секунд, чистка лимитов и сессий. Настройки
  демонстрационного сброса проверяются отдельно: `DEMO_RESEED_HOURS=0` по умолчанию отключает
  автоматический сброс. Положительное значение включает пересоздание после указанного
  возраста данных и 30 минут простоя; оно уничтожает созданные заявки и сеансы.
- **Помощник**: сервер собирает контекст владельца сессии и вызывает OpenRouter при
  `OPENROUTER_API_KEY`, иначе настроенный Anthropic. При отсутствии ключей или ошибке API
  используются встроенные правила. Для OpenRouter ограничены время ожидания и длина ответа.
  Модель не получает инструменты изменения базы.

## Фронтенд

- ES-модули без сборки, разделы подгружаются по требованию (`import()`), поэтому телефон не
  скачивает весь кабинет сразу.
- Главная собирается одним запросом `/api/home` — меньше задержек на мобильном интернете.
- Дизайн-система прототипа: Onest, светлые карточки, округлые кнопки, синий и золотой акценты.
  Onest поставляется локально с лицензией OFL; системный шрифт служит запасным вариантом.
- Каталог игрового слоя (`public/js/shared/catalog.js`) общий для браузера и сервера: витрина
  показывает статус вещи, а сервер по тому же каталогу проверяет, что вещь действительно открыта.
- Аватар, питомцы, кампус и иконки — собственные SVG; забег — Canvas 2D с псевдо-3D перспективой.

## Хранение и возможное масштабирование

Текущая реализация — один процесс Node.js и SQLite. Заявки, история статусов, сеансы и игровой
прогресс записываются в базу. Для сохранения при перезапуске и повторной публикации файл базы
должен находиться на постоянном диске/томе; наличие файла в контейнере само по себе этого не гарантирует.

Следующая таблица — план развития, а не уже реализованные возможности.

| Сейчас (демо) | Что понадобится при росте нагрузки |
|---|---|
| Синхронный SQLite в файле | Адаптер PostgreSQL, миграции схемы, параметров запросов и транзакций, асинхронные вызовы |
| Сессии в той же базе | Общее хранилище сессий для всех экземпляров |
| Лимиты в памяти процесса | Общее хранилище лимитов, например Redis; при рестарте текущие счётчики обнуляются |
| Фоновые задачи в каждом процессе | Один исполнитель или распределённая блокировка задач |
| Один процесс Node.js | Балансировщик, нагрузочные тесты и наблюдение за задержками |
| Вымышленные учебные данные | В рамках конкурса остаются вымышленными; подключение к реальным системам не выполняется |

Модули HTTP, предметной логики и хранилища разделены, что упрощает такие изменения, но SQLite
нельзя заменить PostgreSQL одной настройкой. Предел числа одновременных пользователей и
работа под пиковой нагрузкой не измерялись. Кеширование расписания по группе — возможная
оптимизация с обязательным сбросом кеша после изменения пары.
