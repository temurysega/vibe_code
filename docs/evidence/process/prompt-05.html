05 · Помощник по данным текущего студента

Реконструкция задания по исходникам. Не оригинальная переписка и не снимок интерфейса ИИ-сервиса.
Контекст: ИИ-ассистент · интеграция внешней модели
Добавь в кабинет функцию «Спросить деканат». Она помогает быстро разобраться в собственном расписании, учебных рисках, сроках и заявках. Ответ должен быть коротким, понятным и по возможности содержать ссылку на нужный внутренний экран. Помощник не заменяет решения деканата и не получает права изменять оценки, статусы заявлений или данные других студентов. Сервер собирает ограниченный снимок данных текущего пользователя из его сессии. Передавай провайдеру вопрос и только этот контекст, а не всю базу. Подключи OpenRouter через серверное окружение; предусмотренное прямое подключение Anthropic сохрани как отдельный вариант. Никаких ключей в public/, браузерном запросе, скриншотах, Git или журналах. Не публикуй исходные значения ключей даже при диагностике ошибки 401. Главный кабинет должен работать без внешнего ИИ. Если ключа нет, провайдер вернул ошибку, ответ пустой или превышен срок ожидания, возвращай полезный ответ по встроенным правилам. Чётко показывай источник: модель или встроенные правила. Не сообщай пользователю, что внешний ИИ ответил успешно, если сработал резервный режим. Время ожидания и длину ответа ограничь. Внешний текст выводи безопасно, внутренние ссылки проверяй по разрешённым маршрутам. Продумай смену аккаунта во время запроса. После выхода история очищается; опоздавший ответ Алине не должен появиться в кабинете Тимура. Обработай закрытие экрана, повторный запрос и недоступность сети. Остальные экраны продолжают работать независимо от состояния помощника. Сначала проверь контракт с подставным API: корректный ответ, HTTP 401 и 429, ошибка в теле, пустой текст, тайм-аут и исключение сети. Отдельно проверь изоляцию контекста и допустимость ссылок. Затем, только при настроенном настоящем ключе, выполни живой запрос для двух разных студентов: например, спроси о группе и сравни ответ с профилем. Сохрани результат без секретов и настоящий снимок интерфейса. Разделяй три факта: код интеграции существует, тест с подставным API проходит, конкретный живой запрос выполнен. Не делай из последнего гарантию точности всех ответов модели.
Связанный результат в проекте
Помощник обращается к провайдеру только с сервера, получает контекст владельца сессии и имеет резервные правила. Сохранены отдельные тесты контракта и материалы предыдущих живых запросов OpenRouter для двух студенческих аккаунтов.
