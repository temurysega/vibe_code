# П-08 · Модель угроз → инварианты и тест-план безопасности
## Промпт (дословно из методички)
```text
Безопасность жюри проверяет руками: подставляет чужой адрес, ищет ключи в коде и браузере, смотрит,
как хранятся пароли. Давай заранее составим модель угроз именно для нашего кабинета, а не общий
список OWASP.

Пройди по угрозам и для каждой дай: сценарий атаки в одну фразу → инвариант (правило, которое код
соблюдает всегда) → где он обеспечивается (файл или слой) → автотест, который это проверяет.

Обязательно разбери:
1. Чужие данные через подстановку id в адресе или теле запроса (заявки, документы, уведомления).
2. Студент вызывает API деканата; сотрудник одного факультета смотрит заявки другого.
3. Подделка изменяющего запроса с чужого сайта (CSRF).
4. Кража и подбор сессии; хранение токенов.
5. Перебор пароля, в том числе параллельными запросами, которые обгоняют счётчик попыток.
6. Внедрение разметки через объявления деканата и комментарии к заявке.
7. Утечка ключей ИИ-провайдера: код, public/, логи, скриншоты, история Git.
8. Помощник получает данные другого студента или выполняет инструкции, спрятанные в данных.
9. Злоупотребление общим демо-стендом: публичный аккаунт деканата рассылает бесконечные объявления;
   кто-то меняет общий демо-пароль.
10. Данные прежнего пользователя в интерфейсе после смены аккаунта: кеши, формы, история чата,
    соседняя вкладка.
11. Выход за пределы public/ при раздаче статики; раскрытие стека в ошибках; внешние ресурсы в CSP.

Параметры, которые я предлагаю: scrypt (N=16384, r=8, p=1, соль 16 байт); токен сессии —
32 случайных байта, в базе SHA-256; cookie HttpOnly и SameSite=Lax, в продакшене Secure и префикс
__Host-; сессия 12 часов, простой 2 часа; 5 неудачных входов на пару «адрес + логин» и 30 на адрес
за 15 минут → 429 с Retry-After; тело JSON не больше 64 КБ. Если считаешь что-то слабым — предложи
замену с обоснованием.

Результат: черновик docs/SECURITY.md простыми словами для жюри, нумерованный список инвариантов
для AGENTS.md и список тестов для test/security.test.js с названиями.
```

**Оспариваю параметры**
- scrypt N=16384 — минимально допустимый уровень. Для сервера с одним процессом я бы взял N=32768 или 65536, если вход остаётся быстрым; нужно замерить время.
- Лимит «адрес + логин» не остановит атаку с нескольких адресов на один логин. Добавить счётчик по логину без адреса с более высоким порогом и без полной блокировки.
- `style-src 'unsafe-inline'` ослабляет CSP; я бы вынес стили из атрибутов, а если нет, честно записать это в границы.
- Блокировка после 5 попыток на 15 минут позволяет злоумышленнику закрыть вход жертве. В демо это приемлемо, но это стоит записать в SECURITY.md.
- Остальные параметры приемлемы.

**Инварианты для `AGENTS.md`:** студент из сессии; чужое = 404; ключи только в окружении; после смены аккаунта всё чисто.

**SECURITY.md** — простыми словами по тем же 11 пунктам и раздел «Что не проверялось».
