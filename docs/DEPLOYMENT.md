Контейнер работает от пользователя `node`; сброс базы отключён. Ключи не входят
в Git, образ приложения и архив исходников. Секрет передаётся контейнеру через окружение.
Общие проекты, тома и сеть удалять при обновлении кабинета нельзя.

## Обновление

Развернуть архив нужного коммита в новый каталог `releases/<commit>`, затем:

```bash
cd /opt/mgimo-mania/releases/<commit>
docker compose --env-file /opt/mgimo-mania/.env -p mgimo-mania -f deploy/compose.vps.yaml config --quiet
docker compose --env-file /opt/mgimo-mania/.env -p mgimo-mania -f deploy/compose.vps.yaml up -d --build
docker inspect mgimo-mania --format '{{.State.Health.Status}}'
```

Для маркировки образа задаётся `APP_VERSION=<commit>` в окружении команды.
После проверки обновляется ссылка `current`. Постоянное имя тома сохраняет данные
при смене версии. Не использовать `down -v` и `npm run seed` при обычном обновлении.

Если меняется только код, конфигурацию Caddy трогать не нужно. При первичной замене
старого сервиса изменяется только upstream внутри блока `ai.neblanki.tech`:
`reverse_proxy mgimo-mania:3000`. Сначала проверить конфигурацию, затем выполнить reload:

```bash
docker exec predel-caddy-1 caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile
docker exec predel-caddy-1 caddy reload --config /etc/caddy/Caddyfile --adapter caddyfile
```

Caddy сохраняет исходный Host и по умолчанию не доверяет переданному посетителем
X-Forwarded-For; это нужно для проверки Origin и ограничения входов.
См. [официальную документацию reverse_proxy](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy#headers).

## Приёмка

При замене приложения на том же домене нужно проверять и браузер со старой установкой.
«Живой конспект» регистрировал `/sw.js` и отдавал страницы из офлайн-кеша `zk-*`.
После удаления приложения такая копия могла продолжать открываться у прежних посетителей.
Путь `/sw.js` теперь содержит миграционный worker: удаляет только кеши `zk-*`, снимает
старую регистрацию и перезагружает открытые вкладки. Новый кабинет не регистрирует
офлайн-worker для новых посетителей. Этот endpoint нужно сохранять для возвращающихся
пользователей. Он отдаётся с `Cache-Control: no-store`.

При проверке открытой старой вкладки обновите страницу. Если браузер ещё показывает
прежний экран, выполните жёсткое обновление `Ctrl+Shift+R`. Удаление cookie или данных
других сайтов не требуется. Регрессия воспроизводится в `test/browser-migration.py`.

На опубликованном HTTPS-адресе пройдены 117/117 браузерных проверок: 52 проверки экранов,
42 проверки действий и cookie, 23 проверки доступности и восстановления после ошибки.
Ошибок JavaScript не обнаружено. Вход двух студентов, изоляция заявок, обработка деканатом,
получение PDF и проверка документа пройдены при ширинах 360 и 1366 px.
Артефакты: `docs/evidence/deployment/browser-*.json` и снимки рядом.

Cookie проверенных сеансов имеют `Secure`, `HttpOnly`, `SameSite=Lax`, `Path=/`
и имя `__Host-mm_sid`. Живой OpenRouter возвращает `source=ai`, `provider=openrouter`;
ответ о группе совпал с профилем студента. Модель — `qwen/qwen3-30b-a3b-instruct-2507`.
В `openrouter-live.json` нет значения ключа.

Через интерфейс шириной 360 px также пройдены два живых запроса помощнику — для Алины
и Тимура. Группы совпали с профилями, метка ИИ видна, история предыдущего аккаунта не
попала в новый сеанс. Отчёт: `assistant-browser-live.json`, скриншот `360-assistant-live.png`.

Персистентность проверена на настоящем контейнере: создана заявка (HTTP 201), выполнен
`docker restart mgimo-mania`, затем та же сессия получила заявку (HTTP 200) с сохранёнными
полями и историей. Тестовая заявка отменена после проверки. Отчёт:
`docs/evidence/deployment/production-persistence.json`.

После переключения сохранены прежний HTML `predel-ai.ru` (совпал SHA-256), перенаправление
`www.predel-ai.ru` и идентификаторы соседних контейнеров. Текущие даты старта этих контейнеров
предшествуют публикации; отдельного исходного снимка StartedAt нет.
Подробности и ограничения — `docs/evidence/deployment/preserved-services.json`.

После каждого будущего обновления снова проверить вход, заявку и её сохранение после
перезапуска контейнера. Наличие постоянного тома само по себе не заменяет эту проверку.
