# 05 · Сборка по модулям

> **Происхождение.** Методичка написана после создания прототипа по его коду, журналам и истории Git. Это не журнал промптов. Настоящие диалоги — [`docs/ai/PROMPTS_LOG.md`](../ai/PROMPTS_LOG.md) и [`docs/evidence/subagents-2026-11-19/`](../evidence/subagents-2026-11-19/).

**Как работаем:** каждый модуль — вертикальный срез (сервер + интерфейс + тесты), который запускается
командой `/feature <раздел>` из комплекта агентов. Промпты ниже — содержание задачи для этой команды.
**Шлюз после каждого модуля:** `npm test` зелёный; экран проверен на 360×800 и 1366×768; для изменений
сервера — проверка `security-auditor`; обновлён `PROGRESS.md`; коммит с понятным сообщением.
Тогда история Git становится честной хронологией работы.

## П-16 · Каркас: сервер без фреймворков и оболочка кабинета

> - **Кому:** Claude Code в план-режиме
> - **Опирается на:** `AGENTS.md`, ADR-001…005, разделы UX и SEC в `SPEC.md`
> - **Шлюз:** сервер стартует, экран входа без горизонтальной прокрутки на 360 px, обход каталогов закрыт
> - **Приёмы:** явный список файлов и ответственности · запрет новых зависимостей · проверяемые критерии каркаса

```text
Начинаем код. Прочитай AGENTS.md, docs/ai/DECISIONS.md (ADR-001…005) и разделы UX и SEC в SPEC.md.

Задача — каркас, на который лягут все разделы.

Сервер (Node.js ≥ 22.13, "type": "module", без фреймворков):
- server/config.js — все настройки только из окружения: PORT, HOST, NODE_ENV, DB_FILE,
  SESSION_TTL_HOURS, SESSION_IDLE_HOURS, TRUST_PROXY, COOKIE_SECURE, ключи ИИ, DEMO_RESEED_HOURS,
  DEMO_AUTOPILOT_SCALE. В репозитории только .env.example с пустыми ключами; .env, data/ и
  node_modules — в .gitignore;
- server/http/router.js — маршруты вида /api/requests/:id и цепочки «охранник → обработчик»
  (requireStudent, requireDean);
- server/http/body.js — разбор JSON с лимитом 64 КБ и помощники проверки полей;
- server/http/static.js — раздача только из public/, нормализация пути, обход каталогов отсекается;
- server/app.js — заголовки безопасности (CSP только со своего домена, frame-ancestors 'none',
  nosniff, Referrer-Policy, HSTS в продакшене), проверка CSRF и Origin для изменяющих запросов,
  ошибки без стека для клиента;
- server/db.js — node:sqlite, файл из DB_FILE, применение schema.sql, первичное заполнение
  демо-данными.

Клиент (без сборки):
- public/index.html — полоса концепта сверху на всех экранах: «Концепт для конкурса. Не официальный
  сервис МГИМО. Данные вымышлены»;
- public/js/app.js — hash-роутер, экраны подгружаются через import() по требованию; шапка с
  четырьмя учебными разделами, нижнее меню на телефоне;
- public/js/lib/api.js — обёртка fetch: CSRF-заголовок, единый разбор ошибок, понятный текст для
  пользователя;
- public/js/ui/overlay.js — диалог с удержанием фокуса, Escape и возвратом фокуса.

package.json: start, dev (node --watch), seed, test (node --test). Зависимостей не добавляй.

Готово, если: npm start поднимает сервер; http://localhost:3000 открывает экран входа без
горизонтальной прокрутки на 360 px; npm test проходит (как минимум: заголовки безопасности и 404
для неизвестного API); запрос /../server/config.js и его кодированные варианты не отдают файл.

Сначала план со списком файлов, потом код.
```

**Если ИИ ошибся**
- Тянет Express «для удобства»: «ADR-001 — без фреймворков. Если без зависимости не обойтись,
  напиши, какую задачу она решает, и жди решения».
- В CSP появился 'unsafe-inline' для скриптов: «Убери его; встроенные скрипты вынеси в модули».

**В репозитории:** `server/app.js` (`5c49cde`), `server/http/router.js` (`632d6fc`), `public/js/app.js`,
`public/index.html`.

## П-17 · Вход, сессии и профиль

> - **Кому:** Claude Code, после него — `security-auditor`
> - **Опирается на:** раздел AUTH в `SPEC.md`, инварианты 1, 4–7
> - **Приёмы:** параметры безопасности заданы числами · гонка при переборе названа заранее · тесты перечислены до кода

```text
Делаем вход и профиль — раздел AUTH в SPEC.md и инварианты 1, 4, 5, 6, 7 из AGENTS.md.

Сервер:
- server/security/password.js — scrypt (N=16384, r=8, p=1), соль 16 байт, ключ 64 байта; в базе
  строка scrypt$N$r$p$соль$хеш; сравнение через timingSafeEqual. Если логина нет, scrypt всё равно
  вычисляется — время ответа не должно выдавать существующие логины;
- server/security/session.js — токен 32 случайных байта, в базе SHA-256; cookie HttpOnly,
  SameSite=Lax, Path=/, в продакшене Secure и префикс __Host-; срок 12 часов, простой 2 часа,
  не больше 10 сеансов на пользователя; выход удаляет сессию на сервере;
- server/security/rateLimit.js — 5 неудачных попыток на «адрес + логин» и 30 на адрес за 15 минут,
  затем 429 с Retry-After. Важно: попытку резервируем до проверки пароля — иначе десять
  параллельных запросов проскочат мимо счётчика;
- CSRF-токен привязан к сессии и приходит с каждым изменяющим запросом в заголовке X-CSRF-Token;
- audit_log: входы и выходы.

Профиль (/api/me, экран profile): ФИО, факультет, направление, профиль, курс, группа, языки,
куратор, контакты деканата. Номер зачётки и телефон скрыты до нажатия «Показать». Раздел
«Безопасность»: активные сеансы с половиной IP и кнопкой «Завершить»; смена пароля (нужен текущий,
проверка сложности, остальные сеансы закрываются). На общем демо-стенде новый пароль проверяется,
но не сохраняется — чтобы никто не закрыл вход остальным экспертам; при DEMO_MODE=0 смена работает
полностью.

Экран входа: логин и пароль, понятные ошибки, тестовые аккаунты выбираются одним нажатием (пароль
демо публичный — так и написано рядом), маркировка концепта видна сразу.

При выходе интерфейс забывает всё о прежнем пользователе: кеши модулей, формы, историю чата.

Тесты в test/security.test.js: без входа API отвечает 401; 5 неверных паролей → 429 с Retry-After;
10 параллельных неверных попыток не превышают лимит; в таблице sessions нет исходного токена;
у cookie правильные флаги; изменяющий запрос без CSRF или с чужим Origin → 403.
```

**Если ИИ ошибся**
- Счётчик увеличивается после проверки пароля: «Запусти 10 параллельных неверных входов и покажи,
  сколько дошло до scrypt. Резервируй попытку до проверки» (E-03).
- Пароль демо хранится открытым «для удобства жюри»: «В базе — только хеш. Пароль показываем на
  экране входа, а не храним».
- Профиль сразу показывает номер зачётки: «Минимум данных на экране: зачётка и телефон — по нажатию».

**В репозитории:** `server/security/password.js` (`26a17f0`), `session.js` (`ec13338`),
`rateLimit.js` (`a7057e8`); `test/security.test.js`; `public/js/views/login.js`, `profile.js`.

## П-18 · Время вуза и расписание

> - **Кому:** Claude Code
> - **Опирается на:** раздел SCH в `SPEC.md`, инвариант 10
> - **Приёмы:** сценарий студента как цель · «правила + исключения» · проверка под чужим часовым поясом

```text
Расписание — раздел SCH. Сценарий, ради которого всё делаем: студент на бегу открывает кабинет
с телефона и за несколько секунд понимает, куда идти на ближайшую пару и не изменилось ли что-то.

Сервер:
- server/domain/time.js — всё время вуза считаем по Москве, независимо от часового пояса сервера:
  дата, номер недели и её чётность, семестр, праздники, звонки;
- server/domain/schedule.js — неделя собирается из регулярных занятий группы и журнала изменений:
  отмена, перенос, новая аудитория, замена преподавателя, дополнительное занятие. У изменённой пары
  есть понятное объяснение: «Перенесена с четверга, 3-я пара», «Аудитория 2014 → 1023»;
- /api/schedule?week=… и экспорт в календарь (.ics), чтобы студент мог пользоваться расписанием
  вне кабинета.

Интерфейс (public/js/views/schedule.js):
- вкладки «Сегодня» и «Неделя»; у пары — время, дисциплина, вид занятия, преподаватель,
  аудитория с этажом;
- изменения заметны не только цветом: значок и текст «что изменилось»;
- день без пар — нормальное пустое состояние, а не пустой экран;
- дни недели переключаются и с клавиатуры;
- на главной — ближайшая пара с обратным отсчётом.

Тесты: перенос и отмена применяются к нужной неделе; чётность недели; одинаковый результат при
TZ=UTC и TZ=Asia/Vladivostok; пустой день; .ics по RFC 5545 (обязательные поля, переводы строк CRLF).

Проверь в браузере на 360 и 1366 px под Алиной: на этой неделе у неё есть перенос — он должен быть
виден и в «Сегодня», и в «Неделе».
```

**Если ИИ ошибся**
- Время считается по часовому поясу сервера: «Запусти тесты с TZ=UTC — пары съехали на три часа.
  Все вычисления дат — только через domain/time.js».
- Изменение показано только цветом: «Добавь текст изменения и значок; цвет — дополнительный сигнал».

**В репозитории:** `server/domain/time.js` (`60225ba`), `server/domain/schedule.js` (`5b9088a`),
`public/js/views/schedule.js`. Читаемость недельного расписания на компьютере доработана 8 ноября
(`test/browser-schedule-readability.py`).

## П-19 · Успеваемость, сессия и зачётка

> - **Кому:** Claude Code
> - **Опирается на:** раздел GRD в `SPEC.md`
> - **Приёмы:** вопрос студента вместо таблицы · граничные значения в тестах · «прогноз» не выдаётся за оценку

```text
Успеваемость — раздел GRD. Студенту важна не цифра, а ответ на вопрос «как у меня дела и что
сделать?».

Сервер (server/domain/grades.js):
- 100-балльная шкала: контрольные точки по дисциплине, текущая сумма, прогноз по текущему темпу;
- пороги 60 / 75 / 90 и шкала оценок: 90–100 «отлично» (A), 82–89 и 75–81 «хорошо» (B, C),
  67–74 и 60–66 «удовлетворительно» (D, E), меньше 60 — «неудовлетворительно»;
- «сколько не хватает» до следующего порога и зона риска;
- посещаемость, рейтинг в группе, стипендия;
- сессия: экзамены и консультации с датами и аудиториями, допуск;
- электронная зачётка: закрытые семестры, средний балл по семестрам, академические долги.

Прогноз всегда подписан как прогноз: это не официальная итоговая оценка.

Интерфейс (public/js/views/grades.js): обзор дисциплин с баллами, формой контроля, статусом и
прогнозом; подробности дисциплины (контрольные точки, преподаватель, что сделать) — по нажатию;
вкладки «Сессия» и «Зачётка» с графиком среднего балла. Риск понятен без цвета: текст «Требует
внимания» и число недостающих баллов. У долга — кнопка «Записаться на пересдачу», она открывает
форму заявки с уже выбранной дисциплиной.

Тесты: сумма, прогноз и «сколько не хватает» на граничных значениях 59, 60, 74, 75, 89, 90;
дисциплина без контрольных точек; студент видит только свои баллы.

Проверь под Алиной (риск по «Мировой экономике») и Ксенией (долг и пересдача).
```

**Если ИИ ошибся**
- Прогноз выглядит как оценка («Итоговая оценка: 4»): «Подпиши как прогноз; итоговую оценку ставит
  преподаватель».
- Ошибки на границах порогов: «Добавь тесты на 59/60/74/75/89/90 и поправь условия сравнения».

**В репозитории:** `server/domain/grades.js` (`1cac6ae`), `public/js/views/grades.js`,
`test/domain.test.js`. Компактный мобильный вид появился позже, по измерениям (П-29).

## П-20 · Заявки и справки: от формы до документа

> - **Кому:** Claude Code, после него — `security-auditor` и `test-engineer`
> - **Опирается на:** раздел REQ в `SPEC.md`, инварианты 1, 2, 5, 9
> - **Приёмы:** сквозной сценарий вместо экрана · запрет «декоративной правды» · проверка сохранения через перезапуск

```text
Заявки — раздел REQ, самый важный сквозной сценарий для жюри. Студент проходит путь от выбора
справки до готового документа и всё время понимает, что происходит.

Каталог (server/domain/requests.js; список полей общий для браузера и сервера):
- справки: об обучении (электронная или бумажная, ru/en), для посольства (en), для военкомата
  (только бумажная), выписка оценок, о стипендии;
- заявления: пропуск по уважительной причине, материальная помощь (только для бюджетников),
  индивидуальный график сессии, программа обмена (решает отдел мобильности), запись на пересдачу
  (только при долге: выбор дисциплины и удобной даты);
- у каждого вида: описание, срок, способы получения, поля с типами и ограничениями.

Форма:
- ФИО, факультет, курс и группа подставляются из профиля — студент заполняет только недостающее;
- сервер проверяет обязательность, длину, допустимые варианты и даты строго по календарю
  (31 февраля — ошибка, а не 3 марта); дубликат активной заявки того же вида молча не создаётся;
- при ошибке введённые поля сохраняются, рядом с полем — что не так, фокус переходит к первому
  ошибочному полю.

Статусы: Подана → В работе → Готова → Выдана, или Одобрена / Отклонена; Отменена — пока обработка
не началась. Переходы только вперёд и только допустимые для вида. Каждое изменение пишется в
request_events (кто, когда, комментарий) и создаёт уведомление со ссылкой на заявку.

Карточка заявки — как отслеживание посылки: номер, текущий статус, история. Для бумажной —
где и когда забрать. Для электронной — «Открыть и скачать»: демонстрационный документ с кодом и
ссылкой проверки (/api/verify/:code открывается без входа и показывает только номер, дату и
инициалы), сохранение в PDF через печать браузера и надпись «Вымышленный образец без электронной
подписи». Не рисуй декоративный узор, похожий на QR-код: если QR нет, его не должно быть и на
картинке.

Справка о стипендии: таблица шести завершённых месяцев с суммами и итогом, месяцы без выплаты
обозначены отдельно; снимок данных фиксируется в момент подачи. Все суммы демонстрационные — так
и написано в документе.

Демо-автоматика: без участия сотрудника заявка примерно через минуту переходит «в работу»,
а электронная справка становится готовой примерно через 8 минут (DEMO_AUTOPILOT_SCALE=1).
Первое действие сотрудника отключает автоматику. Это нужно, чтобы жюри успело само принять решение
в кабинете деканата.

Безопасность — главное:
- студент берётся только из сессии; чтение, отмена и получение документа ищут заявку условием
  WHERE id = ? AND student_id = ?; чужая → 404 «Заявка не найдена» — тот же ответ, что и для
  несуществующей;
- скрытая кнопка в интерфейсе не заменяет проверку в API.

Тесты: два студента и чужой номер заявки (чтение, отмена, документ); 31 февраля; дубль;
недопустимый переход статуса; сохранение — создать заявку, закрыть сервер, открыть тот же файл базы
и сравнить поля и историю.
```

**Если ИИ ошибся**
- Нарисован декоративный «QR»: промпт О-4 (так и было — E-07).
- 31 февраля превратилось в 3 марта: «JavaScript Date молча переносит дату. После разбора сравни
  год, месяц и день с исходными» (E-05).
- Чужая заявка отвечает 403: «Нужен 404 с тем же текстом, что и для несуществующей».

**В репозитории:** `server/domain/requests.js` (`937f4c4`, 15 коммитов), `server/routes/requests.js`,
`public/js/views/requests.js`, `public/js/views/verify.js`, `test/browser-stipend.py`. Время
автоматики 8 минут — решение после аудита 9 ноября (ADR-007, E-18).

## П-21 · Кабинет деканата

> - **Кому:** Claude Code; если модуль отдаёте второму агенту, например Qwen Code, он получает контекст через `QWEN.md` → `AGENTS.md`
> - **Опирается на:** раздел DEAN в `SPEC.md`, готовый модуль заявок
> - **Приёмы:** явный список файлов, которыми владеет агент · переиспользование, а не дублирование логики · защита общего стенда

```text
Ты подключаешься к проекту «МГИМО Мания». Сначала прочитай AGENTS.md (инварианты 1–3 и 5 — про роли

Задача — вторая роль, сотрудник деканата. Демо-аккаунт dekanat.mo — Ирина Белова, деканат

Что умеет сотрудник:

3. Объявления факультету или конкретной группе.
4. Изменения расписания: отменить пару, сменить аудиторию — запись в schedule_changes и уведомление
   студентам группы.
5. Журнал действий (audit_log).

- каждый запрос сверяет факультет: g.faculty_id = staff.faculty_id; заявка чужого факультета → 404;
```

## П-22 · Уведомления

> - **Кому:** Claude Code
> - **Опирается на:** раздел NTF в `SPEC.md`
> - **Приёмы:** источники событий перечислены · одно условие видимости для всех мест · «вся история», а не «первая страница»

```text
Уведомления — раздел NTF. Задача: студент не пропускает то, что требует его действия, и отличает
это от общих новостей.

Источники событий (server/domain/notifications.js):
- изменение пары (отмена, перенос, аудитория, замена) → студентам группы;
- приближение дедлайна → напоминание за 3 дня; создаётся один раз по ключу, без дублей при каждом
  запросе;
- решение по заявке → лично студенту, со ссылкой на заявку;
- новая оценка → лично студенту;
- объявление деканата → факультету или группе; объявления клубов — всему вузу.

Адресаты: весь вуз, факультет, группа, один студент. Персональный дедлайн, у которого указана
группа, не должен попадать другим студентам этой группы. Проверь это условие во всех местах, где
выбираются дедлайны: API, уведомления и контекст помощника. Лучше одна общая функция выборки.

Прочитанность хранится на сервере (notification_reads). «Прочитать все» отмечает всю историю
студента, а не только загруженную страницу. Отметить прочитанным можно только адресованное этому
студенту.

Интерфейс (public/js/views/notifications.js): лента порциями по 12 с кнопкой «Показать ещё» (фокус
переходит на первую новую карточку); фильтры по типу с aria-pressed; переход по уведомлению ведёт
в нужный раздел; колокольчик в шапке со счётчиком; живые всплывающие уведомления — счётчик
обновляется точечно, кнопка меню не пересоздаётся, иначе теряется фокус.

Тесты: персональный дедлайн Алины не виден другому студенту её группы; «прочитать все» на истории
длиннее одной страницы; чужое уведомление нельзя отметить; напоминание создаётся один раз.
```

**Если ИИ ошибся**
- Персональный дедлайн утекает в группу: баг-репорт О-1 (реальный случай E-02).
- «Прочитать все» отмечает только первую страницу: «Сделай операцию на сервере по всей истории
  студента и добавь тест на историю длиннее одной страницы» (E-04).

**В репозитории:** `server/domain/notifications.js` (`80a3910`), `public/js/views/notifications.js`,
`test/backend-regressions.test.js`. Порции по 12, `aria-pressed` и точечный счётчик появились по
итогам проверок 9 ноября (E-16, E-29, E-31).

## П-23 · Помощник «Спросить деканат» и его системный промпт

> - **Кому:** Claude Code
> - **Опирается на:** раздел AST в `SPEC.md`, ADR-005, инварианты 6 и 8
> - **Приёмы:** ИИ внутри продукта отделён от ИИ в разработке · тесты контракта без сети · три факта, которые нельзя смешивать

```text
Добавим помощника «Спросить деканат» — раздел AST. Он коротко отвечает на вопросы студента о его же
расписании, сроках, баллах и заявках и, где уместно, даёт ссылку на нужный экран. Он ничего
не меняет: не трогает оценки, статусы и чужие данные.

Архитектура (инварианты 6 и 8):
- браузер отправляет только вопрос и несколько последних реплик. Контекст собирает сервер:
  ограниченный снимок данных владельца сессии — профиль, расписание на три календарных дня (сегодня,
  завтра, послезавтра — с учётом выходных и праздников), ближайшие дедлайны, учебные риски, активные
  заявки. Не вся база и не данные других студентов;
- провайдер: OpenRouter при OPENROUTER_API_KEY (модель из OPENROUTER_MODEL, тайм-аут AI_TIMEOUT_MS,
  ограничение длины ответа), иначе прямое подключение Anthropic при ANTHROPIC_API_KEY. Ключи —
  только в окружении сервера;
- если ключа нет, провайдер вернул ошибку (401, 429, ошибку в теле), пустой текст или истёк тайм-аут —
  отвечают встроенные правила на тех же данных. Источник ответа виден в чате: «модель» или
  «встроенные правила». Ответ правил никогда не показывается как ответ модели;
- ссылки в ответе — только из разрешённого списка разделов кабинета, всё остальное вырезается.
  Текст модели выводится с экранированием;
- после выхода история чата очищается; ответ, пришедший после смены аккаунта, новому пользователю
  не показывается.

Системный промпт модели вынеси в отдельную константу и покажи мне до подключения. Черновик ниже —
улучши его.

Тесты с подставным API, без сети: нормальный ответ; 401; 429; ошибка в теле; пустой текст;
тайм-аут; исключение сети; ссылка вне списка вырезается; контекст Алины не содержит данных Тимура;
вопрос в воскресенье «какие пары завтра?» отвечает про понедельник, а в субботу честно говорит,
что в воскресенье пар нет.

Живой запрос — только когда я настрою ключ на сервере: спроси «Какая у меня группа?» под Алиной
и Тимуром и сравни ответы с профилями. В отчёте раздели три факта: код интеграции есть; тесты
с подставным API проходят; конкретный живой запрос выполнен. Значения ключей не выводи никогда —
даже при диагностике 401.
```

## П-24 · Игровой слой: кампус, питомец, Лавка и забег — без ущерба учёбе

> - **Кому:** Claude Code
> - **Опирается на:** раздел PLAY в `SPEC.md`, графику из П-13, инвариант 11
> - **Приёмы:** главное ограничение названо первым · правила начисления числами · общий каталог для клиента и сервера

```text
Подключаем игровой слой — раздел PLAY. Графика уже есть (П-13); теперь — правила и связь с учёбой.
Главное ограничение, которое проверяем в конце: любую учебную задачу можно выполнить обычной
навигацией, ни разу не открыв игру.

1. Каталог (public/js/shared/catalog.js) — общий модуль для браузера и сервера: внешность, вещи по
   слотам, зоны кампуса, титулы, правила начислений. Витрина показывает статус вещи, а сервер по
   тому же каталогу проверяет, что вещь действительно открыта: закрытую вещь нельзя надеть
   запросом к API.
2. М-коины: первая прогулка по зоне кампуса — +20; фокус-сессия — +10, не больше 4 в день;
   «Первые шаги» первокурсника — +200 один раз; забег — не больше 60 в день. Баланс считает только
   сервер. Знаки за учёбу (например, мантия «Отличник» за сессию без троек и долгов) не продаются.
3. Питомец и фокус-сессии «Учимся вместе 25 минут»: таймер; питомец растёт от сессий и подсказывает
   про ближайшую пару и дедлайн.
4. Кампус: каждая зона ведёт в настоящий раздел — деканат → заявки, аудитория → расписание,
   библиотека → фокус-сессия, гардероб → аватар, студклубы → уведомления, Лавка → магазин.
5. Лавка МГИМО: мерч (кепка, футболка, худи) за М-коины, к каждой вещи — цифровая копия для аватара.
   Выдача реальной вещи оформляется заявкой «Мерч из Лавки» и видна в «Моих заявках» со статусом.
6. Забег «Бегом на пару»: сервер выдаёт токен забега и сам отмеряет время; счёт и монеты обрезаются
   по реальной длительности; дневной лимит 5 минут хранится в базе, а не в браузере.
7. «Первые шаги» для первокурсника: чек-лист и квиз из пяти вопросов о кабинете. Правильные ответы
   квиза должны совпадать с тем, как кабинет работает на самом деле.
8. Титулы и демо-тур для жюри в полосе концепта.

На главной игровой блок компактный и необязательный: ближайшая пара, сроки и статус справки всегда
выше. Не обещай, что геймификация улучшает учёбу: в текстах и документах это гипотеза.

Тесты: нельзя надеть закрытую вещь; нельзя накрутить монеты повтором запроса; лимит забега
проверяет сервер; учебный путь проходит без единого игрового действия.
```

**Если ИИ ошибся**
- Справка доступна только через кампус: «Кампус — дополнительный путь. Верни прямую навигацию
  и добавь тест учебного пути без игры».
- Счёт забега приходит из браузера как есть: «Сервер обрезает счёт по реальной длительности забега,
  которую он сам отмерил по токену».
- Квиз описывает функцию, которой нет: промпт О-9 (E-34; в проекте исправлено 19 ноября, `fe1191c`).

**В репозитории:** `server/domain/play.js` (`428d9c7`), `public/js/shared/catalog.js`, экраны
`campus.js`, `wardrobe.js`, `shop.js`, `game.js`, `onboarding.js`.
