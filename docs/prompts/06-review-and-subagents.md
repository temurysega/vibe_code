# 06 · Проверка, субагенты и итерации

> **Происхождение.** Методичка написана после создания прототипа по его коду, журналам и истории Git. Это не журнал промптов. Настоящие диалоги — [`docs/ai/PROMPTS_LOG.md`](../ai/PROMPTS_LOG.md) и [`docs/evidence/subagents-2026-11-19/`](../evidence/subagents-2026-11-19/).

**Три уровня проверки:**
1. **После каждого модуля** — автотесты и сборщик доказательств (П-26).
2. **Аудит по направлениям** — основной агент раздаёт работу субагентам с владением файлами (П-25).
3. **Взгляд со стороны** — студенты (П-27) и новый агент, который не участвовал в разработке (П-28).

Итерации по их итогам делаем с измерениями «до/после» (П-29).
**Шлюз на выходе:** каждая строка матрицы требований подтверждена тестом или сценарием; каждая
найденная ошибка закреплена регрессией и записана в `ERRORS.md`.

## П-25 · Аудит по критериям конкурса силами субагентов

> - **Кому:** Codex как основной агент-оркестратор
> - **Опирается на:** `AGENTS.md`, `REQUIREMENTS.md`, `SPEC.md`
> - **Приёмы:** владение файлами до правок · «воспроизвести → исправить → регрессия» · необратимые шаги вынесены из задачи

```text
Нужна проверка готового прототипа по заданию конкурса — так, как это сделает жюри, — и исправление
найденного. Работаем командой: ты координируешь, три субагента проверяют свои направления.

1. Прочитай AGENTS.md, docs/ai/REQUIREMENTS.md (матрица требований) и docs/ai/SPEC.md. Отметь строки
   матрицы, которые ещё не подтверждены проверкой.
2. Раздели работу на три направления и до любых правок пришли таблицу владения файлами:
   - сервер и безопасность: server/, test/*.test.js;
   - интерфейс и 360 px: public/, test/browser-*.py;
   - документы: docs/, README.md, THIRD_PARTY.md.
   Общие файлы (package.json, AGENTS.md, scripts/) остаются за тобой. Если направлению нужен чужой
   файл, оно пишет тебе, а не правит само.
3. Отправь субагентам поручения (шаблоны Б-1…Б-3). Каждый сначала воспроизводит проблему, потом
   исправляет минимально и добавляет проверку, которая падала бы до исправления.
4. Собери результаты, проверь, что изменения работают вместе, и запусти общий прогон на свежих базах:
   python scripts/collect-evidence.py --output docs/evidence/<новая-папка>.
5. Отчёт: таблица «проблема → исправление → проверка → результат прогона», список непроверенного,
   предложения для AGENTS.md.

Не пушь и не публикуй — это отдельные шаги после моего решения.
```

### Б-1 · Поручение: сервер и безопасность

```text
Роль: аудитор сервера и безопасности «МГИМО Мании». Работаешь параллельно с агентами интерфейса
и документов.
Твои файлы: server/, test/*.test.js. Остальное только читаешь.

Проверь, воспроизводя каждый пункт запросами к API на временной базе (DB_FILE во временной папке;
data/ не трогай; ключи ИИ отключены):
1. Изоляция: минимум два студента — чужие заявки (чтение, отмена, документ), уведомления,
   дедлайны, контекст помощника.
2. Роли: студент → /api/dean/*; сотрудник МО → заявка студента МП.
3. Сессии и CSRF: запрос без токена, с чужим Origin, после выхода, после смены аккаунта в той же
   cookie.
4. Перебор пароля: последовательный и параллельный.
5. Сохранение: заявка и её история после перезапуска сервера с тем же файлом базы.
6. Ошибки ввода: невозможные даты, слишком длинные поля, дубль заявки, недопустимый переход статуса.

На каждую найденную проблему: тест, который падает сейчас → минимальное исправление → тест проходит.
В конце — npm test целиком.
Отчёт до 20 строк: проблема | инвариант | файл:строка | тест | статус. Отдельно — что проверить
не удалось.
```

```text

Исправления — минимальные и в своих файлах; на каждое — сценарий в test/browser-*.py.
```

## П-26 · Сборщик доказательств и браузерные сценарии

> - **Кому:** Claude Code или Codex
> - **Даёт:** `scripts/collect-evidence.py`, `test/browser-smoke.py`, `browser-flows.py`, `browser-accessibility.py`, `requirements-qa.txt`
> - **Приёмы:** повторяемость одной командой · изоляция от пользовательских данных и внешнего ИИ · неуспешные попытки не удаляются

```text
Хочу, чтобы любую проверку можно было повторить одной командой, а каждый результат в документах
для жюри ссылался на настоящий журнал, а не на слова «всё проверено».

1. scripts/collect-evidence.py --output <папка> [--suites …]:
   - для каждого набора — новая временная SQLite и свободный порт; ключи ИИ удалены из окружения;
     пользовательская data/ не используется; DEMO_AUTOPILOT_SCALE=0.15 — только для браузерных
     наборов;
   - сначала npm test, затем браузерные наборы;
   - сохраняет текстовые журналы, JSON-отчёты, снимки экранов и run-summary.json с командами,
     временем по Москве, результатами и SHA-256 проверенных исходников;
   - существующую папку не перезаписывает: неуспешные попытки остаются рядом с успешными.
2. Браузерные наборы на Python + Playwright (Chromium). Зависимости — только в requirements-qa.txt,
   не в приложении:
   - browser-smoke.py — все экраны на 360 и 1366 px: нет горизонтальной прокрутки, нет ошибок
     JavaScript, снимок каждого экрана;
   - browser-flows.py — сквозной путь двух ролей: Алина отправляет справку → сотрудник берёт её
     в работу и отмечает «Готово» → Алина видит уведомление, историю и документ → Тимур по
     сохранённому адресу видит «Заявка не найдена», а его форма заполнена его данными;
   - browser-accessibility.py — клавиатура, фокус в диалогах, Escape, «Повторить» после 503,
     prefers-reduced-motion.
3. Каждая проверка в JSON: название, ширина, ожидание, факт, пройдена ли.

Готово, если одна команда на чистой машине (после pip install -r requirements-qa.txt и playwright
install chromium) даёт run-summary.json со всеми зелёными наборами. Покажи сводку.
```

**Если ИИ ошибся**
- Ускорение автоматики включилось во всех этапах, и упал тест времени: «Ускорение — только для
  браузерных наборов; тест времени готовности проверяет настоящую скорость стенда» (E-22).
- Тест «нашёл» наложение, которого нет на снимке: промпт О-6 (E-23).

**В репозитории:** `scripts/collect-evidence.py` (`9c5de23`), `test/browser-*.py` (15 наборов),

## П-27 · Проверка со студентами → «С чего начать»

> - **Кому:** тест проводит человек, Claude помогает со сценарием и выводами
> - **Даёт:** сценарий теста, изменение главной, `test/browser-first-actions.py`

Часть 1 — сценарий теста:

```text
Я покажу кабинет нескольким однокурсникам. Составь сценарий короткого юзабилити-теста на 15 минут
без подсказок с моей стороны.

Четыре задания: найти изменённую пару на этой неделе; своими словами объяснить, что не так
с «Мировой экономикой»; заказать справку об обучении; найти готовый документ и открыть его.
Для каждого задания: справился ли участник, где задержался, сколько времени ушло, его дословные
слова. После основных заданий — два вопроса об игровом слое: помогает ли он возвращаться в кабинет
или отвлекает.

Добавь памятку для меня: не подсказывать, не защищать интерфейс, просить думать вслух, имена
участников не записывать.
```

Часть 2 — от наблюдения к изменению:

```text
Итоги: оба участника поняли, для чего кабинет и что он умеет, но при переходе от знакомства
к действию не сразу поняли, с чего начать и куда нажать. Оба в итоге разобрались. Других замечаний
нет; замеров времени у меня нет.

Предложи 2–3 варианта решения на главной и выбери один с обоснованием. Мой вариант: заметная кнопка
«С чего начать» → диалог с тремя прямыми действиями (расписание, оценки, справки), который легко
закрыть; при первом знакомстве эти действия видны сразу, а не только предложение настроить аватар.

Реализуй выбранный вариант и добавь test/browser-first-actions.py: открытие и закрытие диалога,
Escape, фокус, переход по каждому действию, 360 и 1366 px. В PROCESS.md опиши это как ответ на
замечание двух участников; повторной проверки с ними ещё не было — так и напиши.
```

**В репозитории:** `public/js/views/home.js` (`19e9672`), `test/browser-first-actions.py`;
