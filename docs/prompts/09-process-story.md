# 09 · История процесса для жюри

> **Происхождение.** Методичка написана после создания прототипа по его коду, журналам и истории Git. Это не журнал промптов. Настоящие диалоги — [`docs/ai/PROMPTS_LOG.md`](../ai/PROMPTS_LOG.md) и [`docs/evidence/subagents-2026-11-19/`](../evidence/subagents-2026-11-19/).

**Цель этапа:** по материалам эксперт за несколько минут понимает, какую проблему решает кабинет,
как шла работа с ИИ, какие ошибки нашли и как исправили, — и может проверить каждое утверждение.
**Шлюз на выходе:** PDF собран скриптом и читается; маршрут жюри пройден на стенде; финальный
чек-лист закрыт.

## П-32 · Журналы в конце каждой сессии

> - **Кому:** основной агент или `docs-chronicler`; запускаем в конце каждой сессии
> - **Приёмы:** запись сразу, а не по памяти в конце · пометка «пересказ», если текст не дословный

```text
Перед завершением сессии обнови журналы — из них потом соберётся описание процесса для жюри.
1. docs/ai/PROMPTS_LOG.md — мои промпты этой сессии дословно, без секретов: дата, инструмент
   и модель, этап, текст, что получилось, коммиты. Твои поручения субагентам — тоже, с пометкой
   «поручение агента».
2. docs/ai/ERRORS.md — каждая ошибка, твоя или найденная проверкой: что, как заметили, причина,
   исправление, регрессия.
3. docs/ai/PROGRESS.md — где мы, что дальше, вопросы ко мне, известные проблемы.
Ничего не пересказывай по памяти: если не уверен в формулировке — пометь «пересказ».
Коммит после этого — с сообщением «docs(ai): журнал сессии <дата>».
```

**Человеку в это же время:** сохранить скриншоты диалогов в ключевые моменты (список — в
[`docs/ai/PROMPTS_LOG.md`](../ai/PROMPTS_LOG.md)) и экспорт сессии, если
инструмент его даёт. Файлы-изображения проверяют до вставки: метаданные, исходное имя, время создания —
см. [00-principles.md](00-principles.md), пункт 2.

**В репозитории:** записи поручений появились только с 8 ноября (`docs/evidence/*-session.json`).
Ранний этап представлен сведениями из журнала сессии; четыре изображения «диалогов» оказались созданными
ChatGPT и в итоговой версии заменены настоящими диалогами субагентов от 19 ноября. Шесть подробных карточек
заданий пришлось реконструировать по коду. Если вести журналы по П-32 с первого дня, реконструировать
ничего не придётся.

## П-33 · PROCESS.md: история создания для жюри

> - **Кому:** субагент `docs-chronicler`
> - **Опирается на:** все журналы `docs/ai/`, историю Git, `docs/evidence/`, снимки диалогов с проверенным происхождением
> - **Приёмы:** структура задана заранее · у каждого утверждения есть источник · список запрещённых преувеличений

```text
Собери docs/PROCESS.md — историю создания «МГИМО Мании» для жюри. По ней эксперты оценивают, как мы
работали с нейросетями, поэтому важны ясность, наглядность и честность.

Источники: PRODUCT.md, RESEARCH.md, DECISIONS.md, PROMPTS_LOG.md, ERRORS.md, PROGRESS.md, история
Git, docs/evidence/ (журналы, снимки, run-summary.json), снимки диалогов с проверенным происхождением.

Структура:
1. С какой задачи начали: проблема студента, главный вопрос кабинета, что узнали у однокурсников;
   таблица «гипотеза → решение → что подтвердил тест → что проверить со студентами».
2. Из чего складывается история: таблица источников и того, что каждый позволяет установить.
3. Как распределялась работа с ИИ: инструменты → задачи → результаты; основной агент и субагенты;
   файлы для агентов (AGENTS.md и комплект).
4. От идеи к устройству: стек и почему (ADR).
5–8. Разделы продукта: учебное ядро; справка как законченный процесс и защита простыми словами;
   визуальный язык и мобильная версия (до/после); ИИ внутри продукта.
9. Проверки и ошибки: таблица «ошибка → как заметили → исправление → проверка», итерации с цифрами,
   ошибки самого ИИ.
10. Журналы и реальные снимки: таблица наборов проверок последнего прогона.
11. Инструменты и вклад человека: что люди делали сами.
12. Что демонстрирует прототип и как пройти его самостоятельно.
Приложение: ключевые промпты по этапам — из PROMPTS_LOG.md.

Правила:
- каждое утверждение — со ссылкой на файл, журнал или снимок; числа — только из run-summary.json;
- подписывай происхождение: «со слов автора», «по истории Git», «по журналу запуска»,
  «реконструкция по коду». Реконструкцию никогда не выдавай за оригинальный диалог, а изображение — за
  скриншот, пока не проверены его метаданные и источник;
- снимок подписан: что на нём, когда и из какого прогона; новый снимок не выдаётся за ранний макет;
- ИИ в разработке и ИИ внутри продукта — разные части, не смешивай;
- не пиши «оценка 10/10», «полностью безопасно», «выдерживает нагрузку», «доступно из России»
  без проверки.

Пиши для человека: короткие абзацы, таблицы там, где сравнение, без внутреннего жаргона сервера.
```

**Если ИИ ошибся**
- Красивое утверждение без источника («кабинет значительно ускоряет получение справки»): «Какой
  журнал это подтверждает? Нет журнала — переформулируй как гипотезу или убери».
- История Git подана как хронология, хотя коммиты разложены скриптом за две минуты: «Опиши честно,
  что показывают эти коммиты (устройство кода), а что нет (время работы)». Так и сделано
  в PROCESS.md, раздел 2.

**В репозитории:** `docs/PROCESS.md` (12 разделов).

## П-34 · Карточки, PDF и архив исходников

> - **Кому:** Claude Code
> - **Даёт:** `scripts/render-process-evidence.py`, `scripts/build-process.py`, `scripts/package-source.py`, `scripts/export-git-history.py`
> - **Приёмы:** материалы собираются одной командой и совпадают с проверенной версией · карточка оформляет журнал, но не заменяет его

```text
Нужны скрипты, чтобы материалы для жюри собирались одной командой и всегда совпадали с проверенной
версией.

1. scripts/render-process-evidence.py — карточки-изображения из настоящих данных: история Git
   (число коммитов, даты, атрибуция), результаты автотестов и браузерных проверок из
   run-summary.json, карточки ключевых промптов из PROMPTS_LOG.md с пометкой происхождения.
   Карточка оформляет журнал, но не заменяет его: в подписи — ссылка на исходный файл.
2. scripts/build-process.py — PROCESS.md → HTML → PDF (A4, Chromium через Playwright): читаемые
   шрифты, изображения не обрезаются, снимки телефона не растягиваются. Во вложения PDF — журналы,
   JSON-отчёты и экспорт истории Git (pypdf). Проверь, что все ссылки и изображения
   в PDF на месте.
3. scripts/package-source.py — архив исходников без базы, .env, node_modules и artifacts/; сверка
   списка файлов с git ls-files.
4. scripts/export-git-history.py — экспорт истории в JSON для приложения к PDF.

Готово, если: python scripts/build-process.py собирает PDF без предупреждений; в PDF есть все
разделы и снимки; архив совпадает с Git.
```

**В репозитории:** все четыре скрипта в `scripts/`, `docs/PROCESS.pdf`, `docs/PROCESS.html`,
`docs/evidence/process/*.png`, `docs/evidence/history/git-history.json`.

## П-35 · Маршрут жюри, матрица соответствия, комментарий к работе

> - **Кому:** субагент `docs-chronicler`
> - **Приёмы:** маршрут с названиями кнопок и ожидаемыми результатами · маршрут пройден на стенде до отдачи

```text
Подготовь три коротких документа: эксперт должен за 10 минут пройти главный сценарий и найти
доказательства по каждому требованию.

1. docs/JURY_GUIDE.md: таблица аккаунтов (логин → кто → что показывает); основной маршрут в шесть
   шагов с названиями кнопок и ожидаемым результатом каждого шага: Алина отправляет справку →
   в другом окне деканат берёт её в работу и отмечает «Готово» → Алина видит уведомление, историю
   и документ → Тимур по сохранённому адресу получает «Заявка не найдена». Что повторить на 360 px.
   Дополнительно: Ксения и пересдача, помощник, клавиатура, кампус. Предупреди, что демо-данные
   общие и в аккаунтах могут быть заявки других экспертов.
2. docs/CONTEST_AUDIT.md: требование конкурса → как реализовано → чем проверено (тест или
   сценарий) → результат последнего прогона. Отдельно: опубликованная версия, история проверок,
   границы проверки — что не проверялось.
3. docs/SUBMISSION.md: текст комментария к работе — что за кабинет (три предложения), ссылки
   (прототип, репозиторий, PDF, маршрут), аккаунты с паролем, главный сценарий, как создавался.

Проверь каждое утверждение по коду и журналам. Все шаги маршрута пройди сам на стенде — только
вход и выход, без создания данных, — прежде чем отдавать документы мне.
```

**В репозитории:** `docs/JURY_GUIDE.md`, `docs/CONTEST_AUDIT.md`, `docs/SUBMISSION.md`.

## П-36 · Сценарий видео до 5 минут

> - **Кому:** Claude или GigaChat
> - **Приёмы:** первые 30 секунд — зачем это студенту · раскадровка по времени · памятка о том, чего не должно быть в кадре

```text
Помоги написать сценарий видео-демонстрации «МГИМО Мании» — до 5 минут, с телефона и компьютера.
Цель — за первые 30 секунд показать, зачем кабинет студенту, а дальше пройти главный сценарий целиком.

Формат — таблица: время | что на экране (устройство, аккаунт, действие) | что говорим (коротко,
живым языком) | подпись на экране.

Обязательно: проблема (15–20 секунд); главная Алины на телефоне — ближайшая пара и «С чего
начать»; перенос в расписании; дисциплина с риском и «сколько не хватает»; заказ справки; решение
в кабинете деканата; уведомление и документ с кодом проверки; Тимур открывает ссылку Алины —
«Заявка не найдена»; помощник отвечает на вопрос «Какая у меня группа?»; 20 секунд игрового слоя;
финал со ссылками и пометкой «концепт для конкурса, данные вымышлены».

Памятка для записи: настоящий телефон или эмуляция 360 px; крупный курсор; никаких ключей,
терминалов с переменными окружения и личных уведомлений в кадре; субтитры.
```

**В репозитории:** по условиям конкурса видео необязательно; автор отложил необязательный ролик
(PROCESS.md, раздел 3). Видеофайла в репозитории нет.

## П-37 · Финальная проверка перед отправкой

> - **Кому:** Claude Code; пункты «вручную» — люди
> - **Приёмы:** проверка по требованиям конкурса, а не по ощущениям · для каждого пункта — доказательство · без исправлений до решения человека

```text
Завтра отправляем работу. Проведи финальную проверку по списку и пришли таблицу «пункт → статус →
доказательство». Ничего не исправляй без моего «да»; что не можешь проверить сам — пометь
«проверить вручную».

1. Прототип открывается по ссылке через HTTPS, все четыре аккаунта входят.
2. Маркировка «концепт для конкурса, не официальный сервис» — на экране входа, в полосе приложения,
   на документе справки, в README и в PDF.
3. Официального логотипа вуза нет; знак собственный, и это написано.
4. Только вымышленные данные: поиск в seed настоящих доменов почты и телефонов без кода 000.
5. Секреты: в репозитории и во всей истории Git нет ключей (поиск по sk-or-, sk-ant-,
   OPENROUTER_API_KEY и ANTHROPIC_API_KEY с непустым значением); .env не отслеживается; в public/
   и ответах API ключей нет.
6. Лицензии сторонних материалов в THIRD_PARTY.md совпадают с установленными пакетами.
7. PDF собирается и читается; ссылки из PDF и README открываются; у жюри есть доступ к репозиторию.
8. Последний общий прогон зелёный и соответствует опубликованной версии (хеш).
9. Тексты не обещают того, чего нет: QR-код, электронная подпись, официальный документ.
10. Изображения «диалогов» и «скриншотов» в материалах: у каждого проверено происхождение (метаданные,
    исходное имя, время создания), подпись соответствует результату проверки.
11. Вручную (люди): открытие с мобильного интернета в России без VPN; VPS и домен оплачены после
    28 ноября; видео загружено и открывается без входа.
```
