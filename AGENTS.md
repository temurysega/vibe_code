# AGENTS.md — «МГИМО Мания»

Конкурсный прототип личного кабинета студента («Цифровой деканат будущего»).
**Концепт для конкурса, не официальный сервис МГИМО. Все люди и учебные данные вымышлены.**
Это единая версия правды для Claude Code (через `CLAUDE.md`), Codex и Qwen Code (через `QWEN.md`).
Подробности — в `docs/ai/`. Начало сессии: прочитай этот файл и `docs/ai/PROGRESS.md`, перескажи, где мы.

## Карта
- `server/app.js`, `server/index.js`, `server/config.js` — сборка приложения, запуск, настройки из окружения
- `server/http/` — роутер, разбор тела, статика; `server/routes/` — API: auth, student, requests, dean, assistant, play
- `server/domain/` — time, schedule, grades, requests, notifications, assistant, play
- `server/security/` — password, session, auth (`requireStudent`, `requireDean`), rateLimit, headers
- `server/db.js`, `server/schema.sql` — SQLite (`node:sqlite`); `server/seed/` — вымышленные данные
- `public/js/views/` — экраны; `public/js/shared/` — модули для браузера и сервера; `public/js/lib/` — api, session-sync, format (`esc`)
- `public/css/` — стили; `tokens.css` — дизайн-токены
- `test/*.test.js` — API и логика (`node:test`); `test/browser-*.py` — сценарии в Chromium (Playwright)
- `scripts/` — `collect-evidence.py` (полный прогон), сборка PDF, архив исходников; `deploy/`, `Dockerfile` — стенд
- `docs/ai/` — для агентов: PRODUCT, SPEC, DESIGN, DECISIONS, PROGRESS, ERRORS, PROMPTS_LOG
- `docs/` — для жюри: PROCESS, JURY_GUIDE, CONTEST_AUDIT, SECURITY, ARCHITECTURE, DEPLOYMENT; `docs/evidence/` — журналы запусков

## Команды
- `npm start` — сервер на :3000 (Node.js ≥ 22.13); `npm run dev` — с перезапуском при правках
- `npm test` — все автотесты на базе в памяти (`test/helpers.js`); `OPENROUTER_API_KEY=` и `ANTHROPIC_API_KEY=` пустые
- Браузерный набор: сервер с временной базой (`DB_FILE=<временный файл>`, ключи ИИ пустые, `COOKIE_SECURE=0`,
  свободный `PORT`), затем `python test/browser-<набор>.py http://127.0.0.1:<порт>`
- Полный прогон на свежих базах: `python scripts/collect-evidence.py --output docs/evidence/<новая-папка>`
- `npm run seed` — ⚠ `store.wipe()` и создание демо-данных заново; только по команде человека

## Инварианты — нарушать нельзя
У каждого — проверка. «Теста нет» значит: держится на чтении кода, и это нужно сказать в отчёте.
1. Студент определяется только серверной сессией; маршруты не берут id студента из адреса или тела.
   Тест: `security.test.js` «профиль и оценки — только свои»; `backend-regressions.test.js` «подстановка student_id…».
2. Заявка ищется условием `WHERE id = ? AND student_id = ?` (`server/routes/requests.js`, `own()`).
   Чужая или несуществующая → 404 «Заявка не найдена»; так же отмена и документ.
   Тест: `security.test.js` «студент не открывает чужую заявку…»; `stipend.test.js` «API игнорирует чужой student_id…».
3. Деканат — только свой факультет (`g.faculty_id = staff.faculty_id`, `server/routes/dean.js`);
   студенту закрыт `/api/dean/*`, сотруднику — студенческие разделы. Тест: `security.test.js` «деканат видит только свой факультет…».
4. Пароли — scrypt с солью (`server/security/password.js`); в `sessions` — SHA-256 токена; cookie HttpOnly,
   SameSite=Lax, в продакшене Secure и `__Host-`. Тест: `security.test.js` «пароли хранятся только в виде хеша scrypt»,
   «неверный пароль не пускает…»; `security-gaps.test.js` «боевая cookie: __Host-mm_sid с Secure…»; SHA-256 токена — теста нет.
5. Изменяющие запросы — CSRF-токен и проверка Origin (`server/app.js`); SQL — только плейсхолдеры; вывод в HTML — только `esc()`
   (`public/js/lib/format.js`). Тест: `security.test.js` «изменяющий запрос без CSRF-токена…»; `esc()` для объявления деканата
   и комментария к заявке — `test/browser-xss.py`; SQL-плейсхолдеры — теста нет.
6. Ключи и пароли сервисов — только в окружении сервера. Никогда в `public/`, исходниках, логах, скриншотах, коммитах, отчётах.
   Не выводи значения переменных окружения даже при диагностике. Тест: `security.test.js` «ключ ИИ не уходит в браузер»;
   `assistant.test.js` «OpenRouter получает только снимок текущего студента…»; `security-gaps.test.js` «в истории Git нет ключей…».
7. После смены аккаунта не остаётся данных прежнего: кеши модулей, формы, история помощника; вкладки синхронизируются
   (`public/js/lib/session-sync.js`); старый CSRF → 403 `SESSION_CHANGED`. Тест: `security.test.js` «старая вкладка не читает…»;
   `test/browser-session-sync.py`.
8. Кабинет работает без внешнего ИИ. Ошибка провайдера → понятный резервный ответ с указанием источника; он не выдаётся
   за ответ модели. Тест: `assistant.test.js` «ошибка, лимит, пустой ответ и сетевой сбой OpenRouter…», «без ключей помощник работает…».
9. Данные студента переживают перезапуск с тем же файлом базы. Не очищай `data/`.
   Тест: `backend-regressions.test.js` «заявка, история, уведомления и сессия сохраняются после открытия БД заново».
10. Время вуза — по Москве (`server/domain/time.js`, `Europe/Moscow`), независимо от пояса сервера.
    Тест: `domain.test.js` «календарь: недели, праздники и семестры»; `assistant.test.js` «в субботу…», «в воскресенье…».
11. Игровой слой не блокирует учебные действия; баланс, вещи и лимит забега проверяет сервер.
    Тест: `security.test.js` «счёт забега не подделать из браузера», «закрытую вещь нельзя надеть через API»;
    `backend-regressions.test.js` «сбой игрового слоя не мешает отправить заявку…».
12. Только вымышленные данные; маркировка концепта на входе, в приложении и в документах; без логотипа вуза;
    сторонние материалы — с лицензией в `THIRD_PARTY.md`. Теста нет; проверка — чтение `server/seed/`, `public/js/app.js`
    (`paintConcept`), `THIRD_PARTY.md`.
13. Демо-кабинет (`DEMO_SANDBOXES=1`) создаётся только после верного пароля; ссылка и код проверки справки подтверждают
    документ и не открывают кабинет — в ссылке нет `?demo=`; сбросить кабинет можно только из открытого сеанса (ADR-012).
    Тест: `sandboxes.test.js` «неверный пароль не создаёт кабинет…», «одновременные входы из одного браузера…»,
    «проверка справки не открывает кабинет…», ««Начать с чистого кабинета» — только из открытого сеанса»; `test/browser-review-1122.py`.

## Как работать
- Сначала проверь, не сделано ли уже: `rg` по ключевым словам задачи и `docs/ai/SPEC.md`. Если сделано — скажи об этом, не дублируй.
- Задача больше трёх файлов — сначала план (файлы, шаги, риски), потом код.
- Минимальный diff: не переписывай то, что не относится к задаче.
- Новая зависимость — только с записью в `docs/ai/DECISIONS.md` и согласием человека.
- Цвета и размеры — только из `public/css/tokens.css`; подробности в `docs/ai/DESIGN.md`.
- Сомневаешься в решении о данных, правах или схеме базы — спроси.
- Исправляя поведение, найди все его упоминания: тексты интерфейса, квиз (`public/js/shared/catalog.js`), подсказки,
  документы, тесты. Урок E-34: исправили узор, похожий на QR, а квиз продолжал обещать «QR-код».
  Охват закрепляет `test/qr-mentions.test.js`.
- Тест и снимок расходятся — сначала проверь тест (E-23).

- [ ] отчёт по формату ниже

## Параллельная работа
- До правок основной агент публикует таблицу владения файлами. Правишь только свои файлы.
- Нужен чужой файл — напиши основному агенту, что и зачем изменить. Чужие изменения не откатывай и не переформатируй.
- Коммиты и публикацию делает основной агент.
- Аудиторы (`security-auditor`, `ui-mobile-reviewer`) только читают и запускают проверки; правки вносит основной агент.

## Документы и доказательства
- Пиши только наблюдавшееся: команда, сценарий, результат. Числа — из `run-summary.json`, а не по памяти.
- Подписывай происхождение: «по журналу запуска», «по истории Git», «со слов автора», «реконструкция».
- Не заявляй без проверки: устойчивость под нагрузкой, доступность из России, работу внешнего ИИ, оценки жюри.
- Изображение, которое сделал генератор, не выдавай за снимок экрана: проверяй метаданные (E-11).
- Инструмент входит в перечень использованных, только если в репозитории есть его след: диалог, поручение или коммит (E-37).
- В журналах и отчётах — пути без имени пользователя: `<project>` и `~`; это проверяет `test/evidence-privacy.test.js` (E-36).
- Прежние папки `docs/evidence/` не перезаписывай; неуспешные прогоны сохраняй рядом с успешными.

## Только по команде человека
`git push` · публикация на сервер, `ssh`, `docker` · `npm run seed` · удаление материалов проверки · изменение видимости репозитория.
`.env` и `data/` не читай и не очищай; настройки в `.claude/settings.json` запрещают чтение и просят подтверждение.

## Формат отчёта
- **Сделано** — файлы и суть изменений.
- **Как проверено** — команда → результат; сценарий → результат; ширины экрана.
- **Не проверено** — честно.
- **Риски и пересечения** с чужими файлами.
- **Вопросы к человеку.**
- **Предложение** для `AGENTS.md` или `ERRORS.md`, если есть.
