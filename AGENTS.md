# Работа с «МГИМО Манией»

Конкурсный прототип цифрового деканата. Все учебные данные вымышленные.

## Структура

- `server/routes/` — HTTP API, проверка роли и входных данных.
- `server/domain/` — предметная логика; `server/security/` — пароли и сессии.
- `server/db.js`, `server/schema.sql` — SQLite; `server/seed/` — вымышленные примеры.
- `public/js/views/` — экраны; `public/css/` — интерфейс, включая ширину 360 px.
- `test/` — значимые автоматические проверки API и предметной логики.
- `docs/CONTEST_AUDIT.md`, `docs/PROCESS.md` — факты проверки и история работы с ИИ.

## Инварианты

1. Студент определяется серверной сессией. Любое чтение или изменение заявки проверяет
   владельца; деканат ограничен своим факультетом.
2. Нельзя добавлять ключи провайдеров в `public/`, исходники, логи, скриншоты и коммиты.
   Настройки ключей берутся только из окружения сервера.
3. После смены аккаунта очищаются данные предыдущего пользователя, в том числе кеши модулей.
4. Базовые сценарии кабинета работают без внешнего ИИ. Ошибка провайдера должна давать
   понятный резервный ответ, а не блокировать расписание или заявки.
5. Сохраняйте маркировку конкурсного концепта, только вымышленные данные и сторонние лицензии.
6. Изменения студента должны переживать перезапуск сервера с тем же файлом базы.

## Проверка изменений

Нужен Node.js не ниже версии из `package.json`. Запуск: `npm start`; проверки: `npm test`.
Для работы сервера тесты могут использовать свою базу: не очищайте пользовательскую `data/`.
Добавляйте регрессионные тесты для найденных ошибок безопасности, прав доступа и сохранения
данных. После правок интерфейса проверяйте затронутый сценарий на 360 px и обычном экране.

Документируйте результат, который действительно наблюдался: команда, сценарий, найденная
ошибка и исправление. Не объявляйте нагрузочную устойчивость, доступность из России,
работающий внешний ИИ или исторические промпты без соответствующей проверки/источника.
При параллельной работе распределяйте владение файлами до правок и сообщайте о пересечениях.
